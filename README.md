# Piotroski F-score backtest

A research test, not a trading system. The universe is the **Top 500 US common stocks by market cap, excluding financials and utilities (S&P 500 proxy)**. Each May, it asks whether buying the financially strongest companies, measured by the Piotroski F-score (a 0-9 count of financial-health tests), beat an equal-weighted portfolio of the same stocks, and whether any gain survives known factors.

## The answer

**No detectable edge.** Excess return means High's return minus the benchmark's; it is shown as the mean monthly gap times 12 and as the gap between compounded annual returns (CAGR), which differ. The issuance signal's literal paper rule is primary (fixed before looking at results, `output/prereg_v3.md`); the v2 net rule is a sensitivity. Both benchmarks are shown: all included names is primary because the brief defines the comparison as the equal-weighted universe, but that was set after v1.

| Issuance rule | Benchmark | High CAGR | Benchmark CAGR | CAGR gap | Mean gap x12 | Sharpe High / benchmark |
|---|---|---|---|---|---|---|
| literal (primary) | all included (primary) | 12.00% | 10.79% | +1.21% | +1.42% | 0.63 / 0.61 |
| literal (primary) | scored only | 12.00% | 11.36% | +0.65% | +0.92% | 0.63 / 0.65 |
| net (sensitivity) | all included (primary) | 10.62% | 10.79% | -0.17% | -0.04% | 0.59 / 0.61 |
| net (sensitivity) | scored only | 10.62% | 11.35% | -0.73% | -0.53% | 0.59 / 0.65 |

Primary tests, literal rule (Holm-adjusted, all adjusted p 0.91 or higher): High minus benchmark +1.42% (t 1.03); four-factor alpha +1.06% (t 0.77); High minus Low alpha +0.70% (t 0.36). Minimum detectable effect at 80% power: 3.9% to 5.4% a year. The 95% interval for the first is -1.29% to +4.13%, which contains Piotroski's own +1.7 point effect, so it cannot be ruled out.

The earlier 2015-25 'significant' four-factor alpha is post-hoc and exploratory (the split was chosen after v1 showed a large t); the universe's own benchmark alpha in that period is -1.70% (t -1.88). Trial count is an approximate upper bound of about 360, critical |t| about 3.8; no score-isolating test reaches it.

**Vintage:** FY2015-24 restatement exposure is measured only by an SEC sample (`output/spec_v3/sec_vintage_check_v3.md`), not the full table. **Still open:** hashing inside each pull script (the hashes are taken after the fact), and a full-market book-to-market replication, which needs a broad-universe WRDS pull that has not been authorised. The full write-up is `output/writeup.md` (generated by `21_v3_writeup.py`); the v2 text is in `output/archive_v2/`.

## What you need

- Python 3.13 and the packages in `requirements.txt`: `pip install -r requirements.txt`.
- A WRDS account with Compustat (company accounts), CRSP (monthly stock prices and returns) and Fama-French (published return factors) access, including the quarterly, monthly-security and company-name tables that `python 00_test_wrds.py` checks. `crsp.msp500list` is expected to print NO ACCESS: S&P 500 membership history is not available, which is why the universe is a market-cap proxy. The data is licensed, so `data/` is not in the repository, and the scripts pull it.

## WRDS login

Passwords are never stored in this project. Save your own login in the PostgreSQL password file:

- Windows: `%APPDATA%\postgresql\pgpass.conf`
- Others: `~/.pgpass`

Scripts use the `PGUSER` environment variable if it is set, otherwise the username from that file's WRDS line, and pass it to `wrds.Connection`. This matters if your computer's username differs from your WRDS one, since `wrds` would otherwise prompt for it and fail when no one is there to answer. Run `python 00_test_wrds.py` first to check your access.

## Raw data is write-once

Files in `data/raw/` are never edited.

- `02_pull_data.py` refuses to run and exits with code 1 if any of its raw files exist.
- `08_robustness.py`, `09_reit_liquidity.py` and `09a_extension_pull.py` reuse their raw file if it exists. `12a`, `12c`, `12d` and `26a` refuse to replace theirs.
- All of them replace raw files only if you pass `--overwrite`.

## Later pulls may differ

WRDS revises its data, and recent Compustat rows change most often. `01_build_universe.py` and `03_clean.py` also read WRDS directly on each run, so a later rerun can differ from the stored results even with identical code. A same-day rerun from an empty folder with fresh pulls reproduced every v3 result table byte for byte (`verification/clean_folder_rerun_v3_full.md`); a different vintage has not been tested.
